# Flowtime식 집중·휴식 연결 — 의도 (2026-11-23 확정)

- **Outcome:** 작업 중 흐름은 끊지 않되 쉴 때가 되면 부드럽게 알려 주고, 작업을 멈추는 순간 일한 시간에 맞춘 길이로 휴식 타이머가 바로 시작되게 한다.
- **User:** 사용자 본인. 대부분 인지 작업이고, 지금은 시간을 정하지 않고 공부한다.
- **Why now:** 몰아서 일하고 몰아서 쉬어 피로가 쌓인다. 한 번 쉬면 다시 시작하기 싫어서(할 일을 몰라서가 아니라 단순히 하기 싫어서) 오래 쉰다. 휴식 타이머를 며칠 전에 만들었지만, 지쳐서 손을 놓는 순간에는 타이머 없이 그냥 쉬는 경우가 많다.
- **Success:** 직접 써 봤을 때 쉬는 시점이 늦어지지 않고, 쉴 때 휴식 타이머가 실제로 켜져 휴식이 늘어지지 않는다. 몇 주 써 본 뒤 사용자가 판단한다.
- **Constraint:**
  - 작업을 강제로 끊지 않는다. 알림은 작고 무시할 수 있어야 하며(부드러운 알림), 알림 시점은 사용자가 바꿀 수 있다.
  - 새 타이머를 따로 만들지 않고, 기존 작업 타이머와 휴식 타이머(`src/components/planner/restTimer.jsx`: 휴식 시간, 복귀 후 첫 행동, 복귀 활동, 연장)를 연결한다.
  - 설정에서 관련 기능(작업 중 휴식 알림, 작업 종료 시 휴식 타이머 연결)을 켜고 끌 수 있어야 한다.
- **Out of scope:**
  - 25분처럼 정해진 간격으로 강제로 끊는 뽀모도로식 타이머
  - 화면을 가리거나 반복해서 울리는 강한 알림
  - 집중 통계나 분석 화면
  - 휴식이 끝난 뒤 복귀를 돕는 기능 추가 개선(이미 휴식 타이머에 있음)

## 인터뷰에서 나온 참고 사항
- 휴식이 끝난 뒤 다시 시작하게 하는 방식으로 "작게 시작하기(5분만)"와 "미리 약속하고 지키기" 중 어느 쪽이 효과 있는지는 사용자도 직접 써 봐야 안다고 했다.
- 근거: 정해진 휴식이 자율 휴식보다 피로를 덜 쌓았다(Biwer 외, 2023). 짧은 휴식은 활력을 높이지만 인지 작업의 성과 향상은 약했다(Albulescu 외, 2022).
